👤 Per-User Identity & Channels
Every person gets their own identity. Every conversation gets its own channel key.
1
Each person creates their UserIdentity
UserIdentity(user_id, platform, device_secret) — tied to their account ID on that platform. The device_secret never leaves the device.
2
One-time shared secret exchange
Alice calls alice.new_shared_secret() and sends it to Bob via QR code, ghost code, or in person. This happens once per relationship.
3
Both create their Channel independently
alice.channel_to(bob.public_id(), shared_secret=s) and bob.channel_to(alice.public_id(), shared_secret=s) both derive the same channel key from the sorted IDs + secret + platform.
4
Encrypt → platform → decrypt
ch_alice.encrypt("message") → paste into WhatsApp → ch_bob.decrypt(envelope). WhatsApp sees only the opaque JSON blob.
5
Platform isolation baked in
The channel key derivation includes the platform label. Alice's WhatsApp channel ≠ Alice's Telegram channel, even with the same shared secret and same contact.
🧬 Entropy Pipeline
From raw mouse movements and keystrokes to a 32-byte entropy seed
🖱
Mouse Micro-tremor
Steps <3 pixels in size isolate involuntary neuromuscular jitter — the noise that no person can control or reproduce exactly twice. RMS amplitude captures the characteristic "shakiness" of each individual.
ENTROPY SOURCE
⌨
Keystroke Bigrams
Per key-pair transition timing (e.g. how long between releasing 't' and pressing 'h') encodes fine motor control. Sorted alphabetically before packing so output is deterministic.
ENTROPY SOURCE
🧮
Length-prefixed Pooling
SHA3-256(len(mouse)‖mouse‖len(keys)‖keys) — the length prefix prevents boundary collisions where swapping bytes between sources produces the same hash. Borrowed from TLS 1.3 transcript hashing.
DESIGN
🎲
OS Randomness Always Mixed
os.urandom(32) is always included in key derivation. Behavioural entropy is additive — even a trivially weak capture yields a cryptographically secure key from the OS component.

🔐 Cryptographic Stacks
Four independent stacks — one entropy pool feeds all of them
🔒
Stack A — Classical AES-256-GCM
The baseline symmetric encryption stack.

Key derivation: HKDF-SHA3-256 (RFC 5869) from pooled entropy + os.urandom
Cipher: AES-256-GCM, 96-bit nonce, 128-bit auth tag
Nonce: os.urandom per operation — never reused
File format: MAGIC(9) + aad_len(2) + aad + nonce(12) + ciphertext
AAD: filename bound into GCM tag — rename detected
256-bit classical · 128-bit post-quantum (Grover)
⚛
Stack B — ML-KEM-1024 Hybrid
Quantum-safe: breaks both KEM and behavioural entropy required to decrypt.

KEM: ML-KEM-1024 (NIST FIPS 203, 2024) — 1568-byte ciphertext
Hardening: Argon2id(behaviour, salt, 64MB, t=1) → 64 bytes
Session key: HKDF-SHA3-512(KEM_shared ‖ Argon2id_output) → 32 bytes
Cipher: AES-256-GCM on session key
Defense in depth: dk alone insufficient; behaviour alone insufficient
256-bit classical · 128-bit post-quantum (NIST Level 5)
🔏
Stack C — ZKP + Vault
Zero-knowledge proofs + threshold secret sharing + burn-after-read vault.

ZKP: Schnorr / Fiat-Shamir over RFC 3526 Group 14 (2048-bit MODP)
Shamir: GF(2⁸), N-of-M threshold; information-theoretic security
Vault: ARMED → HOT → BURNED; TTL dead-man switch
MITM Shield: ML-KEM session + AES-GCM + HMAC-SHA3-512
Replay guard: ±5-min timestamp + monotonic sequence counter
Info-theoretic · 2048-bit DL · HMAC-SHA3-512
🔄
Stack D — Rotating Keys
Key rotates every 0.3 seconds, bound to device + session + user identity.

Rotation: 0.3-second epoch derived from system time + identity
Identity: user_id + session_id + device_secret + context
Threat block: suspicious sessions rejected before key derivation
Self-healing: retry with backup identity failover on transient errors
Serialisable: envelope includes expiry — serverless cold-start safe
256-bit · replay blocked · brute-force resistant

⚠ Documented Limitations
🦠
Pre-encryption malware
Kernel-level or browser-level access can intercept plaintext before the crypto layer. No key derivation system defends against this.
🎮
Presence score (local mode)
Mouse/keystroke count is a UI gate, not a cryptographic commitment. A determined attacker controlling the browser cannot be stopped by score gating alone.
🔢
40-bit ghost code
~40 bits of security. Suitable for demonstration; use FIDO2/WebAuthn for production second factors on high-value secrets.
🌐
ARP MAC lookup is LAN-only
Remote attackers show "unknown" in the threat log. Only effective for same-subnet intrusions.
